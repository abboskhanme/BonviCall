# BonviCall — Conventions

**Who reads this:** everyone. It holds the cross-cutting rules (contract, errors,
time, phone, idempotency, privacy boundary, permissions, naming, testing,
language) and the server rules. Panel and Android rules live in
**`docs/CONVENTIONS-CLIENT.md`**; they are not repeated here, and nothing here is
repeated there.

Author: `plan-conventions` · 2026-09-04 · enforced by `qa-review`.
Sources: `docs/STACK.md`, `docs/REQUIREMENTS.md` (rev 3), `docs/TASKS.md` §0,
`docs/S1-RECORDING.md`, and the production code of `../BonviZvonki` and
`../CallSentry`.

Every rule below is checkable by reading a file. Where a rule comes from
BonviZvonki it says so; where BonviZvonki is **rejected**, it names what went
wrong there. No code exists yet, so this file is a recipe, not a description.

---

## 0. How much structure — the call

BonviCall is **multiple entry points over one service layer, plus a thin
pure-function rules layer where a rule needs testing without a database.**

| Force | Consequence |
|---|---|
| Panel work is CRUD + permissions | router → service → model. **No repository layer, no interfaces, no DTO-per-layer** |
| Three entry points: panel (human), device API (Android), service export (BonviZvonki) | one `services/` layer, three thin router packages |
| Genuine rules that must be tested without a DB: phone key, time-boxed number→agent, OEM-file/call time-window match, internal-vs-external, capture-rate regression, min-version compare | optional `rules.py` per module — pure functions, no session |
| Genuinely swappable infrastructure: **audio storage** (local FS now → S3 named in `STACK.md`), **Android capture route** (OEM harvest / MediaRecorder, both ship on day one) | exactly two interfaces in the whole product: `AudioStorage`, `RecordingStrategy` |

**Rejected: BonviZvonki's 4-layer module (`presentation → application → domain ←
infrastructure`).** It did not do its job, and the evidence is in the repo:
`src/shared/{application,domain,infrastructure}/` are four empty `__init__.py`
files that never gained a line in 14 modules; `users/application/` and
`auth/application/` are empty; and `select(` appears **11 times in
`agents/presentation/router.py`**, 6 in `calls`, 6 in `surveys`, 2 in `users`,
1 in `auth` — the layer that was supposed to keep SQL out of routers did not.
`calls/presentation/router.py` is 1101 lines. Four directories per module bought
naming ceremony, not separation. BonviCall uses three files with grep-checkable
arrows instead.

**Rejected: a repository layer.** Nothing here has a second persistence
implementation and none is planned. SQLAlchemy is the repository.

## 1. Repository layout and the three deliverables

```
server/     FastAPI + SQLAlchemy + Alembic          (T15)
panel/      React 18 + Vite + TS + Tailwind         (T15)
android/    Kotlin + Compose + Hilt + Room          (T15)
contract/   the wire contract + generated clients   ← where server, panel and app meet
docs/
```

**The API contract lives in `contract/`, as committed generated artefacts:**

| File | Produced from | Consumed by |
|---|---|---|
| `contract/openapi-device-v1.json` | `server/src/api/device/schemas.py` | Android DTOs |
| `contract/openapi-panel-v1.json` | `server/src/api/panel/**/schemas.py` | panel TS types |
| `contract/openapi-service-v1.json` | `server/src/api/service/schemas.py` | BonviZvonki (§5.4) |
| `contract/phone-vectors.json` | hand-written, §7 | pytest **and** JUnit |

- The Pydantic schemas are the source of truth; the JSON is regenerated by
  `make contract`. **CI runs `make contract && git diff --exit-code contract/`.**
  A wire-format change that is not visible in the PR diff is impossible.
  *(This is the mechanism T23 asks for — one artefact drives both clients — with
  the direction chosen code-first, because FastAPI is code-first and hand-written
  OpenAPI would rot.* **`TASKS.md` T23 was written before this decision and still
  reads spec-first; this file is authoritative and `plan-manager` is amending T23.
  The contract direction is not an open question.**)
- **Kotlin DTOs and panel types are generated, never hand-written.** A file
  under `android/**/data/remote/dto/` or `panel/src/shared/api/types.gen.ts` that
  is not machine-produced is a violation.
  *Rejected from BonviZvonki:* it hand-writes response interfaces per module
  (`web/src/modules/calls/api.ts` → `CallListItem`, 20 snake_case fields). It
  survives because one person writes both sides the same day. Here the Android
  client is on 15 phones we cannot force-update — a renamed field must be a
  compile error, not a runtime `undefined`.

## 2. Server layers and dependency direction

```
api/device/    Android only.  Versioned, frozen contract, additive-only
api/panel/     the web panel.  Ships in lockstep with the server
api/service/   machine export (UC-29).  Versioned, additive-only
      ↓ all three call the same services
modules/<name>/service.py   business logic, owns the transaction
modules/<name>/rules.py     pure functions — optional, no session, no framework
modules/<name>/models.py    SQLAlchemy only. No queries, no logic
core/                       clock, phone, errors, permissions, deps, storage, config
```

**Dependency rule and its checks:**

| Rule | Check |
|---|---|
| No SQL in any router | `grep -rn "select(\|session.execute\|text(" server/src/api/` → empty |
| No commit in any router | `grep -rn "\.commit()" server/src/api/` → empty |
| No role branching outside the registry | `grep -rn "user.role ==\|role in (" server/src --include=*.py` → only `core/permissions.py` |
| `models.py` imports nothing upward | `grep -rn "from src.modules.*service\|from src.api" server/src/modules/*/models.py` → empty |
| `rules.py` is pure | `grep -rn "fastapi\|sqlalchemy\|import src" server/src/modules/*/rules.py` → empty |
| A module imports another module's **service**, never its models — one narrow exception, §2.1 | `grep -rn "from src.modules.*.models import" server/src/modules/` → only same-module, FK targets, and the modules declared in `core/reads.py` |
| `core/` is imported by modules and imports none of them | `grep -rn "from src.modules" server/src/core/` → empty. `get_current_user` calls `UserService`, it does not import `UserModel` |

**`rules.py` is created only when it would have content.** Six modules will have
one; the rest will not. Creating an empty layer "for symmetry" is the
`shared/application/__init__.py` defect and is a review failure.

### 2.1 Cross-module reads — the one exception, and its fence

Two release-1 modules own **no table** and exist only to compute an answer from
other modules' data: **`gaps`** (UC-23) and **`exports`** (UC-29). Between them
they read six tables belonging to four other modules. Assembling that from
per-row service calls would make the gap report — the product's own smoke alarm
for "a phone stopped producing audio" — slow enough that someone later replaces
it with a raw query, and the rule gets broken by accident instead of on purpose.

So the exception is granted, and fenced so a reviewer can see it:

**1. Who holds it.** Only a module with **no `models.py`**, and only if it is
declared in `server/src/core/reads.py`:

```python
# Modules that own no table and may read other modules' models in aggregate
# SELECTs. Read-only. CONVENTIONS.md §2.1.  Adding an entry needs a line in
# docs/ASSUMPTIONS.md; a module that later gains a table loses the exception.
CROSS_MODULE_READS: dict[str, frozenset[str]] = {
    "gaps": frozenset({
        "calls.CallModel", "calls.CallAudioModel",
        "devices.CallLogDeltaModel", "devices.DeviceHealthModel",
        "installations.InstallationModel", "agents.AgentModel",
        "catalog.SupportedModelModel",
    }),
    "exports": frozenset({
        "calls.CallModel", "calls.CallAudioModel",
        "agents.AgentModel", "numbers.RegisteredNumberModel",
    }),
}
```

`test_cross_module_reads_declared` parses every `modules/*/service.py` with `ast`
and fails when: a module not in the dict imports another module's model; a module
in the dict imports a model outside its own set; or a module in the dict has a
`models.py`. **The list cannot grow silently — it grows in a diff, in one file.**

**2. What they may read.** Exactly the models listed above, never "any model",
and **read-only**. A module holding the exception owns nothing to write, so:
`grep -n "session.add\|session.delete\|insert(\|update(\|delete(" server/src/modules/{gaps,exports}/service.py`
→ empty. It also never calls another module's service to perform a write.

**3. What crosses back out — enforced by construction.** These modules issue
**column projections and aggregates only**: `select(CallModel.id, func.count())`,
never `select(CallModel)`.
Check: `grep -nE "select\(\s*[A-Z][A-Za-z]*Model\s*\)" server/src/modules/{gaps,exports}/` → empty.
Because no ORM entity is ever loaded, no foreign ORM object *can* leak past the
service boundary. What returns is the module's own `schemas.py` type, and the
service method's return annotation must be defined in that module.
This is also the fast path: T48 wants 50 000 export rows in under 30 s, which
entity loading does not reach.

**This exception does not cover single-row lookups.** `auth` reads one user per
login and calls `UserService.get_by_email()` — a service round-trip, which is
what the base rule is for. If the answer is one row, the exception does not
apply; that is the second exception nobody gets to invent.

**The cost, stated:** a renamed column in `calls` now breaks `gaps` instead of
being caught by a service signature. That is paid for by §13 — every aggregate
in these two modules has a test over factory-built data, so the rename fails in
CI rather than in the smoke alarm.

## 3. Module definition — the recipe every module follows

A **server module** is one directory with exactly these files:

```
server/src/modules/<name>/
├── __init__.py
├── models.py          SQLAlchemy models.  class <Name>Model(Base, UUIDMixin, TimestampMixin)
│                     Omitted ONLY by a module that owns no table and is
│                     declared in core/reads.py (§2.1) — today `gaps`, `exports`
├── schemas.py         Pydantic in/out
├── service.py         class <Name>Service — business logic, owns the transaction
├── rules.py           OPTIONAL, only if a pure rule exists
└── tests/
    ├── test_<name>_api.py     endpoint behaviour + RBAC (401/403/404)
    └── test_<name>_rules.py   only if rules.py exists
```

Routers live outside the module, grouped by entry point, so a module can be
reached by more than one:
`server/src/api/panel/<name>.py`, `server/src/api/device/<name>.py`,
`server/src/api/service/<name>.py`. Each declares
`APIRouter(prefix="/<name>", tags=["<Name>"])` and nothing else global.

The **panel module** and the **Android package layout** are defined in
`docs/CONVENTIONS-CLIENT.md` §1 and §5.

Release-1 module set, fixed now from `TASKS.md` Phase 3 (no module is invented
later without an entry here): `auth`, `users`, `agents`, `numbers`, `enrolment`,
`installations`, `devices`, `calls`, `audio`, `alerts`, `gaps`, `commands`,
`exports`, `audit`, `settings`, `catalog`, `analysis`.

`analysis` is the one entry added after release 1 (`SPEC-ANALYTICS.md` §1.1). It
carries files beyond the canonical three — `rules.py`, `prompt.py`,
`validator.py`, `rubric_default.py`, `scorer.py`, `score_writer.py`,
`pipeline.py`, `jobs.py` and a `providers/` subpackage — for the reason `audio`
already does (`archive.py`, `jobs.py`, `reports.py`): the alternative was a
second module with no `models.py`, which §2.1 would force into `core/reads.py`
and `test_layering.py` would then forbid from containing the substring
`update(`.

## 4. The mobile API is a contract with a client we cannot force-update

**Adopted from nothing — BonviZvonki has no mobile client and no answer here.**

1. **Path versioning:** `/api/device/v1/...`. The version is in the path, never
   in a header.
2. **Additive-only inside a major version.** Forbidden diffs on
   `contract/openapi-device-v1.json`, each of which a reviewer can see in the PR:
   removing an endpoint, field or enum value; making an optional request field
   required; narrowing a type; changing what an existing field means. A new
   required behaviour is a new **optional** field with a server-side default.
3. `v2` may only be introduced while `v1` is still served. The date `v1` is
   switched off is a row in `docs/ASSUMPTIONS.md` before `v2` merges.
4. **Minimum-version gate (N34), and the order is the rule.** One dependency,
   `core/version_gate.py::require_min_version`, applied to every device route.
   It carries an explicit allow-list of *drain* routes that it never refuses:
   `POST /device/v1/calls`, `POST /device/v1/audio/*`, `POST /device/v1/call-log-delta`.
   Everything else returns **426** with `{"error":{"code":"app_version_unsupported",
   "message":"<Uzbek: update the app>"}}`.
   Test that must exist and may not be weakened: `test_old_client_drains_then_refused`
   — an under-version client uploads its backlog with 200, then receives 426.
   Refusing an old version must never destroy data.
5. `X-App-Version` and `X-Installation-Id` are required headers on every device
   request; missing → 400 `header_missing`, never a 500.

## 5. Idempotency — one shape, not a per-endpoint decision

Every device write carries a **client-generated UUIDv4 in the body**, named for
the resource: `client_call_id`, `client_event_id`, `client_ack_id`.
Not a header — it must survive as a Room column across app restarts, and headers
get dropped by retry plumbing.

- Server side, one helper: `core/idempotency.py::upsert_once(...)`, implemented
  as `INSERT ... ON CONFLICT (<key>) DO NOTHING RETURNING id`, then a `SELECT`
  when nothing was returned.
- **Forbidden:** `SELECT` then `INSERT if missing`. It is the natural wrong
  implementation and it double-inserts under the exact retry storm this exists
  to survive.
- Every idempotent table has `client_*_id UUID NOT NULL` with a unique index
  named `uq_<table>_<column>`. Checkable in the T19 migration.
- The response is **always 200 with the same server id** — first write and
  replay are indistinguishable to the client, and UC-12 requires exactly that.
- Every idempotent endpoint has a test that sends the identical payload twice
  and asserts one row and one id.

*Rejected from CallSentry:* `localId`, a per-install Room autoincrement. It
restarts at 1 after a reinstall and collides across devices.

## 6. Time — devices lie (N36)

One module: `server/src/core/clock.py`. `datetime.now()` and `datetime.utcnow()`
are forbidden anywhere else — `grep -rn "datetime.now()\|utcnow()" server/src`
returns only `core/clock.py`.

Every device-originated row carries **three** timestamps, never merged:

| Column | Source | Status |
|---|---|---|
| `device_started_at`, `device_ended_at` | ISO-8601 with explicit UTC offset, from the device | data |
| `device_epoch_ms` (BIGINT), `device_tz` (IANA name) | raw, from the device | evidence for skew |
| `received_at` | `func.now()` at commit | **authoritative** |

- **Ordering, cursor pagination, retention and the gap report use `received_at`
  (with `id` as tiebreak). Never a device timestamp.**
  Check: `grep -rn "order_by(.*device_" server/src` → empty.
- Skew is computed once, in the ingest service:
  `clock_skew_sec = received_at - device_epoch_ms`, stored on
  `device_health.clock_skew_sec` (INTEGER seconds), shown in the panel (T87).
- All DB timestamps are `DateTime(timezone=True)`; date-only values use `Date`.
  Adopted from BonviZvonki.
- Working hours and the business calendar are `Asia/Tashkent`, one constant
  `core/clock.py::TASHKENT`. Silence detection (T38) and availability (N38) read
  it; nobody writes the zone name twice.
- Boolean "has it happened" flags are stored as nullable `timestamptz`
  (`archived_at`, `revoked_at`, `audio_deleted_at`) rather than `bool`.
  **Adopted from BonviZvonki** — it answers "when?" as well as "whether?".
- **Android:** wire epoch is `System.currentTimeMillis()`; every *duration* uses
  `SystemClock.elapsedRealtime()`, which is monotonic and immune to the user
  changing the clock mid-call. Check: `grep -rn "currentTimeMillis" android/`
  appears only where a wire timestamp is built.

## 7. Phone numbers — one function, one constant (N37)

**Adopted from BonviZvonki deliberately, because release 2 joins the two
datasets on this key.** Same semantics, same function name.

`server/src/core/phone.py`:

```python
PHONE_KEY_DIGITS = 9              # the ONLY place this number appears

def to_e164(raw: str | None) -> str | None: ...
def phone_key(raw: str | None) -> str | None:   # last 9 digits, or None
def phone_key_sql(column):                       # the SAME rule in SQL
def is_extension(raw: str | None) -> bool:       # < 6 digits → PBX extension
```

- `phone_key_sql` is the only expression used for the `calls` phone index in the
  T19 migration. If Python and SQL disagree the join silently returns nothing.
- Test vectors live in `contract/phone-vectors.json` and are read by **both**
  `server/tests` and `android/app/src/test`. That file is the mechanism that
  keeps the two implementations from drifting; adding a format means adding a
  vector, once. Required entries, taken from BonviZvonki's contact export:
  `+998 90 111-22-33`, `998901112233`, `901112233`, `+998901112233`,
  `(90) 111 22 33`, `8 90 111 22 33` → all `901112233`.
  `1234567` → `null`; `""` → `null`; `null` → `null`.
- **Fewer than 9 digits is never a key.** BonviZvonki's comment records why:
  `1234567` matches the tail of any number and marked strangers as colleagues.
- Empty line directory ⇒ `unknown`, never `external` (UC-25).

*Rejected from BonviZvonki:* the constant lives there **three times** —
`PHONE_KEY_DIGITS` in `calls/domain/routing.py`, `PHONE_TAIL` in
`clients/application/directory.py`, and inline `right(..., 9)` in
`bootstrap.py`. Three names for one rule is how the rule eventually differs.
BonviCall has one name, and `grep -rn "\[-9:\]\|right(.*, *9)" server/src`
outside `core/phone.py` is a violation.

## 8. The privacy boundary is a type, not a policy (UC-15, N28)

The OEM recordings folder holds the employee's private calls. The time-window
match is the boundary. It is enforced in four places, and each is checkable.

1. **One decision point.** `android/.../capture/PrivacyBoundary.kt`:
   ```kotlin
   sealed interface Decision {
       data class Capture(val subscriptionId: Int, val registeredNumber: String) : Decision
       data class Reject(val reason: RejectReason) : Decision   // incl. SUBSCRIPTION_UNKNOWN
   }
   ```
   `PrivacyBoundary.evaluate(call): Decision` is the **only** code that reads
   `SubscriptionInfo` / `PHONE_ACCOUNT_ID`.
   Check: `grep -rn "SubscriptionManager\|PHONE_ACCOUNT_ID" android/` → one file.
2. **Fail-closed by construction.** `OemHarvestStrategy.locate(capture: Decision.Capture, ...)`
   takes the *proof*, not a raw number, so the file scan cannot be reached
   without having passed the boundary. Where the OS cannot identify the SIM the
   result is `Reject(SUBSCRIPTION_UNKNOWN)` — counted in the gap report, never
   captured.
3. **One window, two named constants**, in `OemHarvestStrategy.kt` only:
   `PRE_BUFFER_MS = 5_000`, `POST_BUFFER_MS = 120_000` (CallSentry's measured
   values). Widening them is a one-line diff a reviewer sees. Files are opened
   **read-only**; never moved, modified or deleted.
   Check: `grep -rn "Environment.getExternalStorageDirectory\|/Recordings" android/`
   → one file.
4. **The server holds the boundary too** (the app can be tampered with, T44):
   an audio upload with no matching registered-number call inside the window is
   refused with 409 `audio_not_attributable` and **the bytes are not written to
   storage**.
5. **The wire schema is the allow-list.** A device DTO may not contain a
   free-form map. Check: `grep -rn "Map<String,\|JsonObject\|JsonElement" android/**/dto/`
   → empty. A field the contract does not name cannot leave the phone.

**Three tests are load-bearing and may not be deleted, skipped or weakened.**
A PR touching them must say why in the commit message:
`test_private_sim_uploads_nothing` (T117), `OemLocatorPrivacyTest` (a
private-SIM recording sitting in the same folder is never returned),
`test_audio_not_attributable_rejected` (T44).

## 9. Errors (N35)

One hierarchy, `server/src/core/errors.py`, modelled on BonviZvonki's `AppError`
(**adopted** — the shape is right and the panel already knows it):

```python
class AppError(Exception):
    status_code = 400
    code = "app_error"
```
`NotFoundError` 404 · `ConflictError` 409 · `ValidationError` 422 ·
`UnauthorizedError` 401 · `ForbiddenError` 403 · `GoneError` 410 ·
`VersionUnsupportedError` 426 · `PayloadTooLargeError` 413.
Routers raise `AppError` subclasses, **never `HTTPException`**.

**Every response carries the envelope, including 500.**
```json
{"error": {"code": "audio_not_attributable", "message": "…"}}
```
**Four handlers in `main.py`, and all four are required:**

| Handler | Catches | Renders |
|---|---|---|
| `AppError` | everything the code raises deliberately | `exc.code`, `exc.message` |
| `RequestValidationError` | FastAPI body/query validation | `validation_error` + the offending field |
| `StarletteHTTPException` | **what never reaches the app** — an unrouted path, a wrong method | `not_found` / `method_not_allowed` |
| `Exception` | anything unhandled | 500 `internal_error`, generic Uzbek message |

*The last two are fixes, not copies.* BonviZvonki has neither.

- **`Exception`:** without it an unhandled 500 returns FastAPI's
  `{"detail":"Internal Server Error"}`. The Android client parses one envelope
  shape; a response that does not match it is indistinguishable from a corrupted
  body, and the queue cannot decide whether to retry.
- **`StarletteHTTPException`, added by `build-backend` after testing it:**
  Starlette answers an unrouted path *before* any app-level handler runs and
  returns exactly `{"detail":"Not Found"}` — the shape the device queue cannot
  parse. This is the response an old client gets when it calls a path this
  server version does not have, which is precisely when the queue must behave
  correctly. **Do not remove it as redundant with the `AppError` handler: it is
  not redundant, because the request never reaches the app.** Pinned by two
  tests — an unrouted path and a wrong method both return the envelope.

The traceback is logged with the request id; **never sent to the client.**

| Failure | Status | Code |
|---|---|---|
| No/expired token | 401 | `unauthorized` |
| Token from another installation (N24) | 401 | `installation_mismatch` |
| Role lacks the permission | 403 | `forbidden` |
| Row exists but belongs to another agent | **404** | `not_found` — 403 would confirm it exists |
| Number already registered to someone | 409 | `number_in_use` (names the current holder) |
| Enrolment code reused | 409 | `code_used` |
| Enrolment code expired | 410 | `code_expired` |
| Audio with no matching call | 409 | `audio_not_attributable` |
| Audio past retention | 410 | `audio_expired` — not a 500 |
| App below minimum version | 426 | `app_version_unsupported` |
| `DELETE` on a call or its audio, any role | 405 | `delete_not_allowed` |

- `code` is machine contract: `snake_case`, stable forever, listed in
  `core/errors.py` and present in `contract/`. Its meaning never changes.
- `message` is Uzbek wherever an end user reads it, and lives **only** in
  `core/messages_uz.py` as `code -> message` (see §14).
- **Never swallow.** `except: pass` is forbidden outright. A broad
  `except Exception` requires a comment naming the specific failure it catches.
  One legitimate case is carried over from BonviZvonki: `verify_password` uses
  `except BaseException` because a corrupt bcrypt hash raises
  `pyo3_runtime.PanicException`, which does not inherit `Exception` — one bad
  row 500'd the whole login.
- Logging is `structlog`. Tokens, passwords, enrolment and verification codes are
  redacted to the last 4 characters (N26); a test asserts no token appears in the
  log output.

## 10. Database, migrations and the model registry

### Migrations — one real Alembic history, from the first commit (T19)

- `server/migrations/versions/` starts with **one** revision containing the whole
  release-1 schema. Every later change is its own revision. No task in Phases
  3–5 adds a migration (`TASKS.md` §0).
- **`Base.metadata.create_all` appears only in `conftest.py`.**
  Check: `grep -rn "create_all" server/src` → one hit.
- There is no `bootstrap.py`, no `COLUMN_PATCHES`, no list of
  `ALTER TABLE ... IF NOT EXISTS` strings.
- CI runs `alembic upgrade head` on an empty DB **and** `alembic check`
  (autogenerate must produce an empty diff). Models and migrations cannot drift.
- After `alembic revision --autogenerate`, read the migration before committing —
  it emits spurious `DROP`s (global rule; T102).

**Why, since the temptation to repeat the shortcut is real:** BonviZvonki's
`migrations/versions/` is empty and its schema comes from
`bootstrap.py` = `create_all` + `COLUMN_PATCHES`. That works exactly as long as
every change is "add a nullable column". It cannot express a rename, a type
change, a backfill, a constraint, or any rollback; `create_all` silently ignores
existing tables, so dev and prod diverge with no way to prove they match; and the
FK case already needed a hand-written `DO $$ … $$` block against `pg_constraint`.
BonviCall runs on a host the team does not sit next to and gets coupled to
BonviZvonki in release 2 — an unversioned schema is not auditable.

### The single model registry — kept, with the folklore turned into a test

- Every ORM model is imported into `server/src/core/models.py`.
  **Reason, stated once:** `Base.metadata` must know every mapper before any
  `ForeignKey` string is resolved and before Alembic autogenerates. A model
  reachable only through a router import raises `NoReferencedTableError` at
  runtime, in whichever unrelated module happens to resolve the FK first.
- **The fix BonviZvonki lacks:** `test_model_registry_complete` walks
  `server/src/modules/*/models.py` on disk and asserts every `Base` subclass is
  reachable from `core.models`. A missing import fails CI instead of production.

### Column rules

- Base is always `class XModel(Base, UUIDMixin, TimestampMixin)`; PK is `UUID`
  (adopted). `created_at`/`updated_at` from `func.now()`.
- `duration_sec` INTEGER, byte counts BIGINT, `clock_skew_sec` INTEGER,
  checksums `String(64)`. **No `float` anywhere in a persisted column** — these
  are compared against thresholds on three platforms and float rounds
  differently on each. (BonviCall handles no money; this is the same rule for the
  quantities it does handle.)
- Enums that the wire depends on (`audio_missing_reason`, `capture_route`,
  `enrolment_stage`, `alert_severity`) are PostgreSQL enums **and** members of the
  generated contract. `audio_missing_reason` is `NOT NULL` — N5 requires it never
  be null and never free text.
- Every column carries a docstring saying where the value comes from and why the
  column exists. Adopted from BonviZvonki; it is the best habit in that repo.
- Computed results are not stored when the inputs can still arrive later
  (adopted): the gap report and the capture-rate delta are recomputed per request.
- Table `app_settings`, never `settings` (adopted).

## 11. Permissions (N23, T18)

**Adopted from BonviZvonki — the registry, the `require_permission` dependency,
and the two-place frontend gate. Three things fixed.**

1. **The registry lives in `server/src/core/permissions.py`**, not inside a
   module. BonviZvonki puts `ROLE_PERMISSIONS` in
   `modules/users/domain/entities.py` and then imports it from `core/deps.py`, so
   `core` depends on a module and the arrows point both ways.
2. **Permissions are constants, not string literals.**
   `class Perm: CALLS_READ = "calls:read"` — routers use `Perm.CALLS_READ`.
   Check: `grep -rn 'require_permission("' server/src` → empty (only
   `require_permission(Perm.X)`). BonviZvonki passes raw strings everywhere; a
   typo like `"call:read"` fails closed and silently, forever.
3. **Every constant for UC-01…UC-29 is declared up front (T18).** Module tasks
   reference constants; they never add one. A new constant after Phase 1 is a
   review failure unless T18's list is amended in the same PR.

- Roles: `admin`, `manager`, `sales`, `viewer`, `service`.
- **Scope is narrowed by the query, not by a second permission** (adopted):
  `require_any_permission(Perm.CALLS_READ, Perm.CALLS_READ_OWN)` lets a
  salesperson through, and `CallService.list()` filters on `agent_id`.
- A permission deliberately *not* granted carries a comment saying why. Adopted —
  BonviZvonki's `sales:*` block is the model.
- Wrong owner returns **404**, not 403.
- **Frontend repeats the gate in exactly two places, and both are required:**
  `panel/src/app/router.tsx` `<Gate anyOf={[...]}>` and
  `panel/src/shared/layout/AppShell.tsx` `NAV[].anyOf`. Hiding a menu item is not
  a permission — a pasted URL opens the page without the route guard. Neither is
  a substitute for the server check, which is the only one that decides anything.
- T20's harness is parameterised over the route table and fails when a new
  endpoint appears without an RBAC case: 401 no token, 403 wrong role, 404 wrong
  owner.

## 13. Testing

**Decision: a separate test database, `bonvicall_test`.**

BonviZvonki runs its suite against the live dev database with a
`MARK = "pytest-fixture"` name prefix and a `pytest_sessionfinish` sweeper. That
convention caused a real incident, documented in its own `conftest.py`: the sales
tests wrote to `client_contacts`, that table was missing from the sweeper, and
test contacts appeared among real clients on the Contacts page.

**What the separate DB costs, plainly:** a second database in Compose and CI;
`alembic upgrade head` plus per-test truncation on every run (tens of seconds);
and you lose the one genuine benefit of the shared DB — you can no longer debug a
failing test by opening the panel and looking at the row it left behind.

**What it buys:** the `MARK` prefix, the sweeper, and the "remember to add your
new table to the sweeper" rule all cease to exist — and that rule is the one that
failed. No test can touch real data by construction rather than by discipline.
And `alembic upgrade head` is exercised on every single test run, which is the
check T102 wants anyway.

- `db` is a per-test session inside a transaction that is rolled back. Tables are
  truncated between modules, never dropped.
- **Fixtures that exist, so twenty modules do not each invent one:**
  `db`, `client` (httpx `AsyncClient`), `admin`, `manager`, `sales`, `viewer`,
  `service_token`, `agent_factory`, `registered_number_factory`,
  `installation_factory`, `call_factory`, `audio_factory`, `frozen_clock`.
  **Test data is created only through a factory.** A raw `INSERT` or a
  hand-built model in a test is a review failure — it is how twenty modules end
  up with twenty definitions of "a call".
- Expected values are computed in the test, never read from whatever happens to be
  in the database (adopted).
- **Must have a test:** every endpoint (RBAC 401/403/404 through T20's harness);
  every function in a `rules.py`; every idempotent endpoint (send twice → one
  row); every `audio_missing_reason` path; the three privacy tests of §8; the
  drain-then-refuse test of §4; **every aggregate in a `core/reads.py` module,
  over factory-built data** — that test is what turns a renamed column in another
  module into a CI failure instead of a wrong gap report (§2.1).
- `asyncio_mode = strict`.
- The Android phone test and the server phone test read the **same**
  `contract/phone-vectors.json` (§7) — that shared file is what keeps the two
  implementations from drifting. Client-side test tooling and the client-specific
  cases are in `docs/CONVENTIONS-CLIENT.md` §10.
- **Deleting a test, `assert True`, or weakening an assertion to make the suite
  pass is forbidden.** `@pytest.mark.skip` requires a task id on the same line.

## 14. Language (N39) — BonviCall differs from BonviZvonki here

| Artefact | Language |
|---|---|
| Code, identifiers, file names, table and column names, API paths | **English** |
| Comments, docstrings, commit messages | **English** |
| `docs/*.md` (SPEC, TASKS, ASSUMPTIONS, this file) | **English** |
| Panel UI strings | **Uzbek** — `panel/src/shared/i18n/uz.json` |
| App UI strings | **Uzbek** — `android/app/src/main/res/values/strings.xml` |
| Error `message` a user reads | **Uzbek** — `server/src/core/messages_uz.py` |
| End-user manual, install guide (`docs/QOLLANMA.md`) | **Uzbek** |

**BonviZvonki and CallSentry write their comments and docstrings in Uzbek.
BonviCall does not follow them there** — this is stated because both reference
repos are open next to this one and copying a file brings its comment language
with it. Translate the comment when you adopt the pattern.

Checkable: Uzbek text inside `.py`, `.kt`, `.ts` or `.tsx` is legal in exactly
six files — `core/messages_uz.py`, `uz.json`, `strings.xml`, and the three
model-prompt files named below. Anywhere else it is a violation.

**The prompt exception, added with the analysis module (`SPEC-ANALYTICS.md`
§1.6 and §1.2):**

| File | What stays Uzbek |
|---|---|
| `server/src/modules/analysis/prompt.py` | the scoring prompt, every section |
| `server/src/modules/analysis/rubric_default.py` | the rubric's labels and descriptions |
| `server/src/modules/analysis/providers/gemini.py` | `_TRANSCRIBE_PROMPT` |

A model prompt is neither a comment nor a message a user reads — it is domain
data whose language is measured by the quality of the output it produces on
Uzbek and code-switched Uzbek/Russian speech. Translating it would be an
untested change to the product's most sensitive input, and the same holds for
the rubric's criterion labels, which are what the model matches against.

The exception covers the **strings** in those files and nothing else: their
comments and docstrings are English like everywhere else, and no fourth file
joins the list without the same argument.

One corollary, so it is not argued case by case: **test data that stands in for
what a provider sends or receives stays in the source language** — the sample
transcript in `analysis/tests/stubs.py`, the stub model answer beside it, and an
assertion quoting a prompt substring. It is a fixture, like
`contract/phone-vectors.json`, and translating it would test a language the
product never sees. Test names, docstrings and comments are still English.

## 15. Forbidden

Server:
- `any` equivalents: `Dict[str, Any]` in a wire schema; a device DTO with a
  free-form map
- raw SQL built by string interpolation or f-string into `text()`
- business logic in a router: `select(`, `.commit()`, `if user.role ==`
- `HTTPException` — raise an `AppError`
- `float` in a persisted column
- `except: pass`; broad `except Exception` without a comment naming the failure
- `datetime.now()` / `utcnow()` outside `core/clock.py`
- `Base.metadata.create_all` outside `conftest.py`; `bootstrap.py`;
  `COLUMN_PATCHES`
- a second phone-normalisation implementation, or `[-9:]` outside `core/phone.py`
- ordering or paginating on a device-supplied timestamp
- `SELECT`-then-`INSERT` idempotency
- a permission string literal at a call site
- a new module without `models.py` / `schemas.py` / `service.py` / `tests/`
  — `models.py` may be absent only under §2.1, declared in `core/reads.py`
- importing another module's model from a module not listed in `core/reads.py`
- `select(<Model>)` inside `gaps` or `exports` — projections and aggregates only
- an empty layer directory created "for symmetry"

Panel and Android forbidden lists are in `docs/CONVENTIONS-CLIENT.md` §11.

Everywhere:
- `assert True`; deleting or weakening a test
- committing `.env`, a secret, or the APK signing key
- a token, password, enrolment code or verification code in a log line
